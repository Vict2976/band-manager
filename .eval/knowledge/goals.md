# Goals

_What "good" means to this company, in the order the sources gave them._

1. Everyone in the band can see what is happening, and when, in a few seconds.
   > "Everyone in the band should be able to see what is happening, and when, in a few seconds."
   >
   > — `purpose-and-vision.md`


2. The Band Manager, not the Messenger thread, is where the facts about gigs and rehearsals live.
   > "The Band Manager gives Olis Orkester one shared place for every gig and rehearsal, instead of the Messenger thread."
   >
   > — `purpose-and-vision.md`

   > "The Band Manager is where the facts live."
   >
   > — `purpose-and-vision.md`

   > "The rule of thumb: if it matters for the gig, it goes in the app, not only in Messenger."
   >
   > — `purpose-and-vision.md`


3. The tool stays deliberately simple — nothing beyond what is needed to know where to be.
   > "The tool is deliberately simple."
   >
   > — `purpose-and-vision.md`

   > "Nothing else is needed to know where to be."
   >
   > — `purpose-and-vision.md`


4. Nothing has to be copied by hand and double bookings become much harder.
   > "New gigs, changed times and cancellations update by themselves."
   >
   > — `purpose-and-vision.md`

   > "You never have to copy anything by hand, and double bookings become much harder."
   >
   > — `purpose-and-vision.md`


5. Everyone in the band uses the tool and picks up the shared habits, because it only works if all use it.
   > "The tool only works if we all use it."
   >
   > — `purpose-and-vision.md`

   > "These are the habits we hope everyone picks up:"
   >
   > — `purpose-and-vision.md`


6. A good gig description answers: address and parking/load-in, load-in/soundcheck/stage times, set length and special songs, venue contact with phone, pay and food/drinks, what to bring, and dress code.
   > "A good gig description answers:"
   >
   > — `user-guide.md`


7. Keep events current so calendars update by themselves and only a short heads-up in Messenger is needed.
   > "**Keep it current.** Switch the status to **Confirmed** once it is locked in."
   >
   > — `user-guide.md`

   > "Edit the gig when something changes, and delete it if it is cancelled."
   >
   > — `user-guide.md`

   > "Calendars update by themselves, so a short heads-up in Messenger is enough."
   >
   > — `user-guide.md`


8. The per-musician notes form a shared list of what each member needs, so the band can see what is missing and what to buy or borrow.
   > "Together these notes are our shared list of what each of us needs, so we can see what is missing and what to buy or borrow."
   >
   > — `user-guide.md`


9. Stand-ins are grouped by instrument so it is quick to find the right person.
   > "Group by instrument so it's quick to find the right person:"
   >
   > — `user-guide.md`
